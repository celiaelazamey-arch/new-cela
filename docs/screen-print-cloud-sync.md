# تسجيل الدخول والمزامنة السحابية — تجربة Supabase

**الحالة:** مسار برمجي جاهز للإعداد، لكنه غير متصل بمشروع سحابي في هذا المستودع. لم تُجرَ مصادقة أو مزامنة ضد Supabase حيّ، ولا يوجد نشر أو اعتماد أمني إنتاجي.

## نطاق العمل

- حسابات بريد وكلمة مرور عبر Supabase Auth، ومزامنة يدوية لسجلات الأرشيف الوصفية فقط.
- لا تُرفع صور الرفع أو ملفات التصميم. لا توجد مزامنة تلقائية/آنية أو دعم تعاون حي.
- تبقى جلسة الدخول في ذاكرة جلسة Streamlit الحالية فقط؛ لا يُحفظ refresh token في القرص. إعادة تشغيل التطبيق/انتهاء الجلسة قد يتطلبان تسجيل الدخول مجدداً.
- عند تسجيل الدخول، يستخدم كل حساب مجلداً محلياً منفصلاً حسب UUID الحساب؛ وعند تسجيل الخروج يعود التطبيق إلى الأرشيف المحلي غير المسجل. لا يُستورد الأرشيف المحلي السابق تلقائياً إلى الحساب لتجنب خلط بيانات المستخدمين.
- المزامنة تضيف سجلات غير الموجودة على الطرف الآخر. إذا كان `film_id` نفسه موجوداً بمحتوى مختلف، تُوقف المزامنة وتعرض التعارض دون اختيار نسخة أو الكتابة فوقها. الحذف لا يتزامن، ولا توجد مزامنة حذف/تعارض تلقائية بعد.
- عند استضافة Streamlit للعامة، قد تصل المنصة إلى ملفات الأرشيف المحلية المشتركة على المضيف. لا تستخدم الخدمة مع بيانات عملاء حقيقية أو عدة مطابع قبل عزل المستأجرين، واختبار نشر واقعي ومراجعة أمنية وقانونية.

## إعداد مشروع Supabase

1. أنشئ مشروعاً مملوكاً لك، وحدد المنطقة وسياسة النسخ والاحتفاظ بناءً على مراجعة قانونية/خصوصية فعلية؛ لا تفترض أن الإعدادات الافتراضية مناسبة.
2. في إعدادات Auth فعّل Email، واضبط تأكيد البريد، وسياسة كلمة المرور، وSMTP موثوقاً وحدود الإرسال. اختبر استعادة كلمة المرور وخطاب التأكيد في إعداد المشروع؛ واجهة التطبيق الحالية لا توفر تدفق استعادة كلمة المرور.
3. نفّذ `src/screen_print/cloud_schema.sql` في SQL Editor. راجع سياسات RLS قبل أي بيانات حقيقية. كل صف مربوط بـ`auth.users.id`، وسياسات RLS تمنع المستخدم من قراءة/تغيير صفوف مستخدم آخر.
4. أضف في إعدادات تشغيل Streamlit السرّين التاليين، باستخدام **Project URL** و**anon/public key** فقط:

```toml
SUPABASE_URL = "https://YOUR_PROJECT.supabase.co"
SUPABASE_ANON_KEY = "YOUR_PUBLIC_ANON_KEY"
```

   يمكن وضعهما في `.streamlit/secrets.toml` محلياً أو secret manager في بيئة الاستضافة. لا تضف الملف أو مفاتيح مشروع حقيقية إلى Git. **لا تستخدم service_role key** في التطبيق.
5. ابدأ التطبيق على HTTPS في بيئة تملكها، وراجع إعدادات أصل/إعادة توجيه البريد في Supabase Auth. لا تستخدم معاينة Arena العامة لتخزين بيانات العملاء.

## المراجعة قبل الإنتاج

يلزم اختبار فعلي يتضمن حسابين مستقلين، ومحاولات وصول متقاطعة، وتأكّد RLS على القراءة والكتابة والحذف، واستعادة كلمة المرور، وتأكيد البريد، وحدود المعدل، وفشل الشبكة، وتعارض وتكرار وتوقف المزامنة، وحذف الحساب والبيانات. لم تُنفذ هذه الاختبارات الحية بعد. كما يلزم تحديد مسؤول البيانات، الغرض والأساس القانوني، موقع المعالجة، مدد الاحتفاظ والحذف، النسخ الاحتياطية، وسجل الاستجابة للحوادث مع مستشار قانوني؛ هذه الوثيقة لا تمثل اعتماد امتثال.
