> و**وسيلة اتصال** بـ PDPC (البوابة الإلكترونية أو الخط الساخن). بدون هذين

## 1. الساعات القليلة الأولى (0 → 1 ساعة)

1. **أوقف التصعيد فوراً:** عطّل `Autonomous Agent Pipeline` من إعدادات Actions،
   وأوقف أي تشغيل جارٍ (`gh run cancel <run_id>`).
2. **لا تمسح الأدلة.** احتفظ بـ `.agent_runs/` والتقرير والـ artifact قبل انتهاء
   مدة الاحتفاظ (7 أيام).
3. **حدّد الطبيعة:** هل مسّ الحادث بيانات شخصية؟ هل نُقلت خارج مصر؟
   (المهام تُرسل إلى Gemini/Groq في Actions ⇒ نعم افتراضياً).
4. **سجّل وقت العلم** بالدقيقة — هو نقطة بدء كل الساعات التنظيمية.

## 3. خلال 72 ساعة — الإبلاغ الرسمي (مصر)

**الجهة:** مركز حماية البيانات الشخصية (PDPC) — عبر البوابة الإلكترونية أو
الخط الساخن المخصص. **فوري** إن كان الحادث مرتبطاً بالأمن القومي.

**يجب أن يتضمن السجل الإلكتروني الآمن (المادة 5):**

- وقت العلم بالاختراق ووقت الإبلاغ (بالدقيقة).
- طبيعة الاختراق وتوقيته.
- السجلات/الفئات المتأثرة وعددها.
- الأضرار المتوقعة على أصحاب البيانات.
- التدابير العاجلة المتخذة (تدوير مفاتيح، إيقاف التشغيل، عزل النطاق).
- بيانات مسؤول حماية البيانات / نقطة الاتصال.

**قالب سريع:**

```
Subject: إخطار اختراق بيانات شخصية — [اسم المشروع] — [التاريخ]

1. وقت العلم: [YYYY-MM-DD HH:MM UTC]
2. وقت الإبلاغ: [YYYY-MM-DD HH:MM UTC]
3. الطبيعة: [وصف مختصر بلا بيانات شخصية إضافية]
4. النطاق: [عدد/فئة السجلات المتأثرة]
5. الأثر المتوقع: [...]
6. التدابير: [تدوير مفاتيح / إيقاف pipeline / ...]
7. المسؤول ووسيلة الاتصال: [...]
```

> 📌 **قاعدة ذهبية:** لا تنتظر التقرير الجنائي النهائي قبل الإبلاغ. المصادر
> القانونية تؤكد أن ساعة الـ 72 تبدأ من **العلم**، وأن انتظار التحليل الكامل
> هو خطأ شائع [11](https://blacktree.nl/2025/11/02/egypt-data-protection-executive-regulations-2025/).

## 4. خلال 3 أيام عمل من إبلاغ PDPC

**إخطار الأفراد المتأثرين** — بوسيلة الاتصال المتفق عليها وقت جمع الموافقة
(SMS / بريد / مكالمة)، **بلغة واضحة وبسيطة**، ويتضمن:

- ما حدث باختصار.
- نوع البيانات المتأثرة.
- الإجراءات المتخذة.
- ما يُنصح به الفرد (تغيير كلمات المرور، الحذر من التصيّد…).
- وسيلة التواصل للاستفسار.

> ⚠️ الساعة تبدأ **من تاريخ إبلاغ PDPC**، لا من تاريخ اكتشاف الاختراق
> [2](https://www.recordinglaw.com/world-laws/world-data-privacy-laws/egypt-data-privacy-laws/).

## 6. بعد الاحتواء (خلال أسبوع)

1. **مراجعة بلا لوم (blameless postmortem):** ما الذي سمح بالتسريب؟
   هل كان `agent_result.txt` ينشر مخرجات خام على Issue عام؟
2. **سدّ الفجوة:** نفّذ التوصية 🔴 في
   [`security-threat-model.md`](security-threat-model.md) — حدّ طول المهمة +
   تنقيح المخرجات قبل التعليق.
3. **تحديث هذه الخطة** بأي درس مستفاد، ورفع التغيير إلى البرانش فوراً.
4. **اختبار الاستعادة:** تحقق أن النسخة الاحتياطية (git + المصدر الخارجي للذاكرة)
   قابلة للاستعادة فعلاً.

## 7. جهات وأدوات سريعة

```bash
# إيقاف التشغيل التلقائي فوراً
gh workflow disable "Autonomous Agent Pipeline"

# إلغاء تشغيل جارٍ
gh run cancel <run_id>

# فحص التسريب
python scripts/secret_scan.py
python scripts/pii_scan.py

# مراجعة آخر تشغيلات الوكيل
gh run list --workflow="Autonomous Agent Pipeline" --limit 10

# حفظ أدلة التشغيل قبل انتهاء الـ 7 أيام
gh run view <run_id> --log > incident-<run_id>.log
```
