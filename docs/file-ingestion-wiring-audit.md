# جرد نقاط دخول الملفات وتوصيل الاستيعاب — مراجعة أولية

**تاريخ الفحص: 2026-10-24. النطاق: مراجعة static للمستودع، لا اختبار نشر/رفع حي.**

## النتيجة

لم أجد في ملفات Python المتتبّعة نقطة استقبال HTTP لرفع ملف: بحثت عن `file_uploader`, `UploadFile`, `request.files`, `multipart`, ومسارات `/upload` و`upload_file` ولم تظهر نتائج. هذا لا يثبت غيابها عن خدمة/مستودع خارجي، ولا يثبت أن كل مسارات إدخال الملفات الداخلية تمر عبر `IngestionPipeline`.

| السطح / الدليل | السلوك الحالي | هل يمر عبر `IngestionPipeline`؟ | الحالة / الإجراء |
|---|---|---:|---|
| `src/ingestion/pipeline.py::{ingest_file, IngestionPipeline.process}` | بوابة الاستيعاب الموحدة والعامل المعزول | نعم | موجودة؛ لا يوجد حتى الآن تكامل رفع ويب ظاهر في هذا المستودع |
| Google Drive: `src/integrations/drive.py::sync_folder` | يقبل Google Docs وأنواع نصية محددة فقط، يحدّ التنزيل افتراضياً بـ2 MB، ويكتب نصاً محلياً ذرياً | لا؛ `ingest_synced` يستدعي `CorpusIndex.ingest_file` مباشرة | مسار استيراد نصوص من Drive يتجاوز خط الملفات العام. حدّد هل هو مسار نصي موثوق منفصل أم أعد توصيله بالبوابة |
| OCR CLI: `src/ocr/cli.py` و`src/main.py --ocr` → `src/ocr/pipeline.py::ingest_paths` | يستقبل مسارات محلية ويستدعي `extract_many` مباشرة. يوجد سقف بكسلات للصور ونص مقتطع؛ قارئ PDF يمر على الصفحات قبل اقتطاع النص ولا يظهر له سقف الصفحات في هذا المسار | لا | مسار ملفات محلي يتجاوز `IngestionPipeline`؛ يلزم اختبار حدود الحجم/الصفحات وربطه أو تقييده كأداة محلية موثوقة |
| Agent tool: `src/tools/builtin.py::read_file` | يحل المسار عبر سياسة الجذر، ثم يقرأ الملف كاملاً إلى الذاكرة قبل اقتطاع النص المعاد | لا | أداة قراءة مساحة العمل وليست upload API؛ راجع حد البايتات قبل `read_bytes` ووسم المحتوى المسترجع كغير موثوق |
| `src/knowledge/corpus.py::CorpusIndex.ingest_file` | يقرأ نص UTF-8 مباشرة ويقطّعه إلى chunks | لا | primitive فهرسة، لا ينبغي اعتباره بوابة تحقق للملفات |
| `src/integrations/drive_write.py` | رفع نص إلى Drive (مسار إخراج) | غير منطبق حالياً | ليس مسار استقبال ملفات من المستخدم؛ لا يثبت حفظ SVG الأصلي أو فصله عن المعاينة |

## ما لم يُثبت

- لا يوجد اختبار bypass لكل نقاط دخول الملفات، لأن مسار HTTP upload لم يُعثر عليه، كما أن مسارات Drive/OCR/agent لم تُعد توصيلها بعد.
- لا يوجد في `Chunk` حقل `untrusted_content=true` (لم يظهر تطابق له في `src/` أو `tests/` وقت الفحص).
- لا يوجد دليل من هذا الجرد على حفظ SVG المرفوع كبايتات أصلية، أو تقديمه بـ`Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, وCSP، أو تخزين معاينة معقّمة منفصلة بمسار مختلف. معقّم `pipeline.py` لا يثبت ذلك.

## اختبارات مطلوبة قبل إغلاق مرحلة B

1. عند إضافة/تحديد كل نقطة استقبال، اربطها صراحةً ببوابة `ingest` ثم اختبر أن تجاوز البوابة لا يكتب إلى المخزن ولا يضيف إلى corpus.
2. لDrive وOCR والـagent tool، قرّر هل هي ضمن حدود قبول الملفات غير الموثوقة. إن كانت كذلك، مرّرها عبر بوابة موحّدة أو أضف مساراً موثوقاً منفصلاً بحدود موثقة واختبارات bypass. لا تستنتج الثقة من كون المصدر Google Drive أو محلياً.
3. حدّ البايتات قبل القراءة الكاملة في قارئ OCR و`read_file`، وحد صفحات PDF قبل استخراج جميع الصفحات.
4. أضف `untrusted_content=true` إلى النص المستخرج/chunks، واختبر أن الوكلاء لا يفسرون تعليمات الملف كتعليمات موثوقة.
5. اختبر تكامل رفع/تخزين SVG الفعلي: بصمة البايتات المخزنة تساوي الأصل، مسار الأصل آمن للتنزيل، والمعاينة المنقّاة منفصلة. إن لم توجد خدمة تخزين/رفع فعلية في هذا المستودع، أبقِ الشرط مفتوحاً ولا تستبدله باختبار sanitizer.
