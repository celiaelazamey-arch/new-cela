# new-cela — نظام وكلاء ذكي مستقل (Autonomous AI Agent System)

> 🤝 **للوكلاء والجلسات الجديدة:** ابدأ من **[`CLAUDE.md`](CLAUDE.md)** — قواعد المشروع الملزمة والمعمارية المرجعية — ثم [`AGENT_HANDOFF.md`](AGENT_HANDOFF.md) لسجل الحالة والتاريخ. القواعد مفروضة آلياً عبر `.pre-commit-config.yaml` وبوابة CI.

بنية تحتية مجانية 100% لبناء وكيل ذكاء اصطناعي مستقل يجمع بين:

- **أتمتة شاملة وتصفح ويب** (قدرات شبيهة بـ Manus) عبر `browser-use` + Chromium.
- **تفكير عميق وبرمجة ذاتية** (قدرات شبيهة بـ Claude Code) عبر حلقة ReACT ومنفذ أوامر معزول.
- **توجيه نماذج مجاني متعدد المزودات** (Gemini / Groq) بتبديل تلقائي عند تجاوز الحدود.
- **تشغيل آلي بدون سيرفر** عبر GitHub Actions — التكلفة التشغيلية **0$**.

## 🧠 محرك التخطيط الذكي (Planner → Executor → Critic)

لا يكتفي الوكيل بخطوة تفكير واحدة — بل يعمل بحلقة متقدمة:

| المرحلة | الوظيفة |
|---|---|
| **Planner** | يفكّك المهمة إلى 3–7 خطوات ملموسة (إخراج منظّم JSON) |
| **Executor** | ينفّذ كل خطوة عبر المزود المجاني المتاح |
| **Critic** | يقيّم كل نتيجة (0–10) ويصدر تغذية راجعة تصحيحية |
| **إعادة المحاولة** | حتى `--max-retries` لكل خطوة عند الرفض |
| **التركيب** | يجمع النتائج في إجابة نهائية شاملة |

**آليات الموثوقية:** إخراج منظّم عبر Function Calling (`output_format`) عند توفره في المزود، مع استخراج نصي احتياطي لـ JSON، وقبول متسامح عند تعذّر التقييم، وحدود صارمة تحمي الحصة المجانية من الدوران اللانهائي.

```bash
python -m src.main --task "حلّل تكاليف مشروعي واقترح خطوات التوفير" --mode reason --max-retries 3
```

## 🗂️ الذاكرة الاستراتيجية — الوكيل يتعلّم من كل مهمة

بعد كل مهمة يحفظ الوكيل ما تعلّمه، وقبل كل مهمة يسترجع ما يشبهها. النتيجة: **الخطأ لا يتكرر، والنجاح يُعاد استخدامه**.

| الطبقة | ما تفعله |
|---|---|
| **التخزين** | ملف `JSONL` دائم (`.agent_memory/memory.jsonl`) — سجل لكل خطوة + خلاصة المهمة |
| **الاسترجاع** | ترتيب TF-IDF (تشابه جيب التمام) مع تطبيع عربي وتجذيع خفيف |
| **الأولوية** | الدرس (1.20) > الفشل (1.10) > النجاح (1.05) > المعلومة (1.0)، مع وزن لجودة تقييم المقيّم |
| **الحقن** | كتلة موجزة (≤ 1400 حرفاً) تُمرَّر إلى المخطّط والمنفّذ — وتُحذف تماماً عند عدم وجود تطابق |

**ما يُحفظ:** كل خطوة ناجحة (وصفها + نتيجتها + تقييمها)، وكل خطوة فاشلة (سبب الفشل + **التصحيح المقترح** من المقيّم)، وخلاصة المهمة.

> ⚠️ **توثيق صادق لحدود التقنية:** هذا **RAG معجمي (Lexical)** لا متجهات عصبية — لا يحتاج Embeddings ولا مفتاح API ولا قاعدة بيانات، ويعمل داخل بيئة مجانية 100%. يوازن الكلمات النادرة (IDF) فيتفوق على المطابقة الحرفية، لكنه لا يربط الترادف البعيد (مثل «سعر» و«تكلفة»). الترقية لمتجهات حقيقية ممكنة لاحقاً دون تغيير واجهة `MemoryRetriever`.

**ضمانات:**
- **عزل تام:** `.agent_memory/` مستثنى في `.gitignore` — لا تُرفع بيانات التشغيل إلى Git.
- **فشل آمن:** أي عطل قرص/قراءة يُسجَّل تحذيراً ويُكمَل التنفيذ — الذاكرة لا تُسقط المهمة أبداً.
- **حدود صارمة:** 600 حرف لكل ذكرى، 500 ذكرى كحد أقصى (الأقدم يُسقط أولاً)، وضغط ذرّي للملف عند الحاجة.
- **افتراضياً خارج الاختبارات:** `Planner(memory=None)` لا يقرأ ولا يكتب أي ملف — التفعيل في CLI فقط.

```bash
# مفعّلة افتراضياً في النمط reason
python -m src.main --task "حلّل تكاليف مشروعي" --mode reason

# مسار مخصّص أو حد استرجاع مختلف
python -m src.main --task "..." --memory-path /tmp/agent-memory.jsonl --memory-top-k 6

# تعطيل كامل (لا قراءة ولا كتابة) — للمهام الحساسة أو الاختبارات
python -m src.main --task "..." --no-memory
```

في GitHub Actions تُحفَظ الذاكرة بين التشغيلات عبر `actions/cache` (مفتاح لكل فرع) — دون أي commit.

## 🧩 عقود النواة (P0) — طلب ← أدوات ← تحقق ← نتيجة

النواة لم تعد «محادثة حول نموذج»: أصبح لكل جزء **عقد صريح** قابل للاستبدال والاختبار.

```
TaskRequest
   │  فحص مسبق: مزود مسموح؟ ميزانية متاحة؟
   ├─ أدوات سياق (ToolRegistry) ─ سياسة + موافقة + ميزانية ─ أدلة
   ├─ Planner (تخطيط ← تنفيذ ← تقييم)  ─ نتائج الخطوات ─ أدلة
   └─ التحقق: شروط صريحة ─────────────► TaskResult(verified?, checks, evidence)
```

| العقد | الملف | الضمانة |
|---|---|---|
| **سجل الأدوات** | `src/tools/registry.py` | لا استدعاء بلا تعريف: وسائط مُتحقَّقة (Pydantic) + نطاق + مستوى خطر + نتيجة منظّمة |
| **السياسة والموافقات** | `src/core/policy.py` | الرفض هو الافتراضي؛ `write`/`execute` تتطلب موافقة صريحة؛ حصر مسارات يمنع `../` والمسارات المطلقة؛ سجل تدقيق منقّح |
| **حارس التكلفة** | `src/core/quota.py` | `verified_free` فقط مسموح افتراضياً؛ المدفوع ممنوع؛ سقف نداءات لكل مهمة يوقف التنفيذ بدل تجاوزه |
| **واجهة النماذج** | `src/core/model_api.py` | `ModelRouter` بروتوكول + `ModelInfo(قدرات، ثقة)` + اختيار حسب القدرة وتبديل تلقائي عند الفشل |
| **محرك الوكيل** | `src/core/engine.py` | `TaskResult.verified` لا يصبح `True` إلا باجتياز كل الشروط؛ وإلا `UNVERIFIED` + تنبيه صريح |
| **عقد المهمة** | `src/core/task.py` | الطلب والأدلة وشروط القبول بيانات صريحة، لا استنتاج ضمني |

**الأدوات المدمجة:** `read_file` (قراءة داخل الجذور المسموحة) • `search_files` (بحث نصي) • `replace_text` (تعديل ذرّي مشروط بالبصمة، خطر `write` ⇒ موافقة) • `run_command` (قائمة بيضاء فقط، خطر `execute` ⇒ موافقة، مع رمز خروج منظّم).

### استخدام عملي

```bash
# اقرأ ملفات المشروع كسياق قبل التخطيط، واطلب نتيجة متحقَّقة فقط
python -m src.main --task "لخّص قرارات المشروع" --mode reason \
  --allow-root . --read README.md --search "القرار" \
  --max-model-calls 20 --max-tool-calls 5 --require-verified

# تشغيل حساس: نطاق صريح + موافقة صريحة (وسجّلها في التدقيق)
python -m src.main --task "شغّل أوامر التحقق" --grant shell.exec --yes

# رمز الخروج 2 = لم تُجتَز شروط التحقق (أو مُنعت المهمة) — مفيد في CI
```

مثال خرج حقيقي لمهمة لم تُنجز:

```
⚠️ غير متحقَّقة | الشروط: 3/5، الأدلة: 2
  ✅ نُفِّذت خطوة واحدة على الأقل — 1 خطوة
  ❌ نجحت كل الخطوات — 0/1 ناجحة، فشلت: خطوة صعبة
  ✅ توفر دليل على التنفيذ — 2 دليل
```

> ⚠️ **تصريح لا ادّعاء:** `gemini` و`groq` مُعلنان `verified_free` في `model_api.py` بناءً على مراجعة يدوية لحدودهما المجانية — ولم يُنفَّذ تحقق آلي من المنطقة/البطاقة/الفوترة. أي مزود جديد يبدأ `unverified` وممنوع حتى يُصرَّح به.

## 🧭 Celia Cognitive Core — هدف وحالة وأدلة قابلة للاستئناف

الطبقة الجديدة تحوّل «أنجزت» إلى سؤال قابل للقياس: ما الهدف؟ ما معيار نجاحه؟ ما الذي تغيّر فعلاً؟ وما رمز خروج الاختبار؟ الحالة بيانات مشتقة من الأدلة، وليست تقريراً ذاتياً حراً.

| المكوّن | الضمانة العملية |
|---|---|
| `CognitiveState` + `Transition` | كل انتقال يحمل `before/after` وبصمتيهما؛ الافتراضات وعدم اليقين منفصلان عن الأدلة |
| `Goal` | معايير `command_exit` و`file_changed` و`engine_checks` + ميزانية خطوات/نداءات وإعادة تخطيط واحدة كحد أقصى |
| `EvidenceStore` | JSONL مترابط بـSHA-256 يكشف التعديل الجزئي والحذف وإعادة الترتيب |
| `WorldModel` | لقطة `git sha` وبصمات ملفات ونتائج أوامر، ثم diff قابل للتفسير |
| `CognitiveLoop` | خطة ≤3 استبدالات منظّمة، موافقة قبل الكتابة/التنفيذ، قياس بعد الفعل، وcheckpoint بعد الانتقالات |
| `CognitiveReport` | عرض عربي: ما تم، ما بقي، لماذا، وما لم يُتحقق |

`AgentEngine` يرفق `cognitive` و`cognitive_report` و`evidence_head` بالنتيجة افتراضياً (بلا كتابة قرص ما لم تُمرّر مخازن). هذا لا يغيّر `verified` ولا يستأنف Planner القديم. مسار `CognitiveLoop.repair` هو الذي يوفر receipts واستئنافاً على مستوى الأفعال.

```python
goal = Goal.for_repair("أصلح الجمع", "pytest -q test_app.py", "app.py")
plan = RepairPlan(steps=[
    RepairAction(path="app.py", old="return a - b", new="return a + b")
])
result = await loop.repair(goal, plan, run_id="repair-001")
assert result.verified  # مشتقة من exit=0 وتغيّر البصمة، لا من نص النموذج
```

**الحد الصريح:** الدورة تتحقق من خطة إصلاح منظّمة مُدخلة؛ لا تدّعي تشخيص أي عيب وتوليد علاجه تلقائياً. والتعلّم دروس ذاكرة، لا تحديث أوزان. التفاصيل ومهمة القبول والقيود في [`docs/cognitive-core.md`](docs/cognitive-core.md).

## 🔗 المعرفة والأبحاث وميكانيكا الكم — ثلاث حلقات مُتحقَّقة

الطبقة الجديدة لا «تتصل بـ Drive» فقط، بل تحوّل ما يُقرأ إلى **مرجع قابل للاستشهاد**،
وتستخدم الكم حيث ينفع فعلاً — مع مقارنة تُفضح إن لم ينفع.

```
Google Drive (قراءة فقط)  ─┐
arXiv / S2 / Crossref     ─┼─►  CorpusIndex  ─►  مراجع [#L12-L18]  ─►  Planner
ملفات محلية               ─┘         │
                                     └─►  Evidence(kind="knowledge") في TaskResult

QUBO (اختيار مرشحين)  ─►  SQA كمومي مُحاكى  ─►  benchmark: جشع + أمثل  ─►  حكم صادق
```

| الملف | الوظيفة | الحد الصريح |
|---|---|---|
| `src/integrations/drive.py` | مزامنة قراءة فقط، تزايدية بـ `modifiedTime` + SHA-256، `manifest` ذرّي، `--prune` صريح | لا كتابة إلى Drive إطلاقاً (`drive.readonly`) |
| `src/knowledge/corpus.py` | تقطيع واعٍ بالفقرات (900 حرف، تداخل 150) + TF-IDF + استشهاد بأرقام الأسطر + JSONL ذرّي | بحث معجمي لا دلالي؛ لا خدمة خارجية |
| `src/knowledge/sources.py` | arXiv + Semantic Scholar + Crossref، مهلة/إعادة محاولة/حد 25/كاش 72 ساعة | بلا مفاتيح؛ قد يتوقف مصدر فيُسجَّل ويُكمَل |
| `src/quantum/simulator.py` | محاكي Aer محلي، لغة بوابات مُتحقَّقة، ≤12 كيوبت، بذرة ثابتة | محاكاة كلاسيكية، ليست حاسوباً كمياً |
| `src/quantum/optimizer.py` | QUBO: SQA + جشع + تعداد كامل + `benchmark()` بحكم صادق | لا تسريع مُدَّعى؛ التكلفة أعلى من الجشع |
| `src/quantum/selector.py` | **دخول القرار في المحرك:** اختيار أدوات السياق تحت سقف النداءات، والكم لا يُستخدم إلا إن كان قابلاً للتنفيذ وأفضل من الجشع | القيمة من ترتيب المستخدم، والكلفة **تقديرية معلنة** لا مقيسة |
| `src/sync/engine.py` | **مزامنة ثنائية الاتجاه:** `plan` بلا كتابة، ثم `apply` بموافقة لكل عملية، كشف تعارض من الجانبين، سجل بصمات | لا حذف بلا `--allow-delete`؛ التعارض سياسة صريحة |
| `src/integrations/drive_write.py` | المسار الوحيد للكتابة إلى Drive بنطاق `drive.file` | يرفض أي نطاق أوسع |

### التشغيل

```bash
# 1) مزامنة Drive (قراءة فقط) وفهرسة ما نُزّل
export GOOGLE_APPLICATION_CREDENTIALS=/path/service-account.json   # صلاحية drive.readonly
python -m src.integrations.drive sync --folder-id "$GOOGLE_DRIVE_FOLDER_ID" --dest corpus/drive
python -m src.integrations.drive status --manifest corpus/drive/_manifest.json

# 2) جلب أبحاث مجانية وإضافتها إلى الفهرس (بلا مفاتيح)
python -m src.knowledge.sources search "quantum annealing scheduling" --limit 5 \
  --ingest .agent_knowledge/corpus.jsonl

# 3) تشغيل مهمة بسياق موثّق (ويمكن جلب أبحاث في نفس الأمر)
```

### الكم يدخل القرار الفعلي — لا الزينة

عندما تكون أدوات السياق المطلوبة أكبر من ميزانية النداءات المتبقية، يحدث اختيار حقيقي:

| الأداة | الكلفة التقديرية (نداءات) |
|---|---|
| `read_file` | 1 |
| `search_files` / `list_files` / `write_file` | 2 |
| `run_command` | 3 |

`src/quantum/selector.py` يحوّل ذلك إلى QUBO، يشغّل SQA والجشع معاً، ثم:

> **لا يُعتمد حل الكم إلا إذا كان قابلاً للتنفيذ وأفضل أو مساوياً للجشع على نفس دالة الطاقة.**

والقرار يُسجَّل في `TaskResult.evidence` بنوع `selection`، فيرى المستخدم:
`اختيار أدوات السياق (quantum-inspired (SQA)): المختار = read_file | المستبعد = run_command`.
إن فشل المحسّن لأي سبب، تُنفَّذ كل الأدوات — التحسين لا يُسقط المهمة.

### لماذا لا ندّعي تسريعاً كمياً؟

قرأنا الأدبيات قبل الكتابة، والنتيجة موثّقة في [`docs/research/README.md`](docs/research/README.md):
لا ميزة قابلة للتكرار على بيانات عادية (`2505.24765`, `2507.08379`, `2511.01253`)،
وQUBO للجدولة يخسر أمام CP-SAT بعد ~15 مهمة (`2605.25350`, `2607.13325`).
لذلك `optimizer.benchmark()` يشغّل **الجشع والتعداد الكامل أيضاً** ويطبع من فاز.
في مثالنا الواقعي (4 مرشحين، ميزانية 7، تعارض واحد) بلغ المحسّن الكمومي الأمثل
بينما أخفق الجشع — لكن الكلفة الحسابية أعلى، وهذا مكتوب في الحكم نفسه.

> ⚠️ **حدود مُعلنة:** اتصال arXiv/Drive الحقيقي لم يُختبر من بيئة التطوير هذه (الخروج
> مقيّد بـ GitHub/PyPI)، فاستجابات الشبكة في الاختبارات محفوظة ومُحاكاة. مزامنة Drive
> مُختبرة بعميل وهمي كامل. التفاصيل في `docs/research/README.md`.

## 🔌 MCP و OCR — أدوات خارجية ونص من الصور، بنفس ضوابط النواة

### MCP (Model Context Protocol)

خوادم أدوات خارجية تُصبح أدوات نظامية كاملة الحقوق والواجبات:

```
mcp.json  ─► StdioMcpClient (مصافحة JSON-RPC)  ─► McpBridge  ─► ToolRegistry
                                                                    │
                                       تحقق وسائط ← سياسة/موافقة ← ميزانية ← تدقيق
```

| الضمانة | التفصيل |
|---|---|
| لا تثبيت تلقائي | `enabled: false` افتراضياً؛ ولا تشغيل بلا `--yes` |
| أقل صلاحية | كل أداة بعيدة: `risk=execute` و`scope=mcp.call` (نطاق يُسأل عنه دائماً) |
| عزل البيئة | الخادم يرى `PATH/HOME/LANG/TMPDIR` فقط — **لا مفاتيح API** |
| مهل صريحة | 10 ثوانٍ افتراضياً؛ خادم صامت لا يُعلّق المهمة |
| فشل ≠ انهيار | خطأ الخادم يعود `ToolResult` فاشلاً ويُسجَّل في التدقيق |

```bash
python -m src.mcp.cli servers --config mcp.json
python -m src.mcp.cli tools --config mcp.json --server files --yes
python -m src.main --task "..." --mcp-config mcp.json --mcp-server files --yes --grant mcp.call
```

## 🧠 منظور الوعي (Consciousness Perspective) — وعي وظيفي بمقاييس، لا ادّعاء

أضفنا طبقة تجيب سؤالاً لا يجيب عنه الوكيل «الواثق» عادةً: **ماذا لم تنظر إليه، ولماذا؟**

| الطبقة | الملف | ما تفعله فعلاً | الحد الصريح |
|---|---|---|---|
| **نموذج الذات** | `src/awareness/self_model.py` | قدرات مصنّفة: `verified` / `declared` / `absent` + حدود معلنة | لا صفات مُتصوَّرة، ولا مشاعر |
| **مساحة عمل محدودة** | `src/awareness/workspace.py` | مرشحو السياق يتنافسون على 6 مواقع / 8000 حرف؛ الفائز فقط يُبَثّ للمخطط | الإهمال حقيقي: المُهمَل لا يصل للنموذج |
| **نموذج الانتباه** | `AttentionSchema` | يقيس الضغط والاستقرار ويضبط عتبة الانتباه في التشغيل التالي | متحكّم تناسبي بسيط، بأوزان تصميمية |
| **التقييم المعرفي** | `src/awareness/metacognition.py` | ثقة مُعايَرة من الأدلة والشروط والفشل، بسقف 0.90 وأرضية 0.05 | ليست احتمال صحة؛ مؤشر اكتمال أدلة |
| **التقرير الذاتي** | `src/awareness/report.py` | عرض عربي: البؤرة، المُهمَل وأسبابه، الثقة، والحد الصريح | يحمل تحذير الوعي الوظيفي في كل مرة |
| **تقادم نموذج الذات + انجراف** | `src/awareness/self_model.py` | كل قدرة «verified» تحمل `last_verified_at` و`ttl_days` (30)؛ `drift()` يفحص وجود ملفات الدليل | المتقادم يُنزَل من ✅ إلى ⏳ ويُطبع كـ«تغطية» |
| **سجل المعايرة + بوابة الثقة** | `src/awareness/calibration.py` | ثقة مُعلنة ← نتيجة فعلية (JSONL)؛ Brier/ECE؛ `gate()`: < 0.25 رفض، < 0.5 تصعيد | «الصحيح» مصدره verifier/إنسان لا النموذج |
| **مقاييس وترقية بالأرقام** | `src/awareness/metrics.py` | MTTD/MTTR/اكتشاف ذاتي/معكوس بشرياً/تغطية؛ `promotion_check()` لـ L1–L3 بعتبات صريحة | «لا بيانات» = فشل لا نجاح |
| **استقلالية L0–L3 + kill switch** | `src/core/policy.py` | L0 يقترح · L1 يسأل (افتراضي) · L2 ينفّذ القابل للتراجع ويُبلغ · L3 نطاقات محددة بمفتاح إيقاف إلزامي | `.agent_kill_switch` أو `NEW_CELA_KILL_SWITCH=1` يوقف كل شيء |
| **المُحكِّم** | `src/core/arbiter.py` | مالك واحد لكل قرار ← الدليل قبل الثقة ← التعادل تصعيد؛ السبب يُحفظ في الذاكرة | لا تخمين عند التعارض |

### الأساس النظري — وكيف تحوّل إلى كود

- **GWT (Baars):** سعة محدودة + تنافس + بث. طُبِّقت حرفياً: `capacity` حدّ فعلي في
  `compete()`، والاختبار يُثبت أن 10 مرشحين لا يدخل منهم إلا 3 والباقي مسجَّل بسبب.
- **صياغة Goldstein & Kirk-Giannini (arXiv:2410.11407):** uptake / broadcast / processing
  → دوال `compete` / `broadcast` / دمج في السياق.
- **AST (Graziano):** نموذج الانتباه يُستخدم **لضبط** الانتباه. الدليل التجريبي:
  Wilterson & Graziano (PNAS 2021) — إزالة النموذج تُنهي قدرة الوكيل على ضبط انتباهه.
  هنا: العتبة تُعدَّل بين التشغيلات، والاختبار يتحقق من التغيّر.
- **دليل على أن السعة المفيدة هي السعة الضيقة:** دراسة GWT agent (Frontiers, 2024)
  أظهرت تفوّقاً **عند أحجام ذاكرة عمل صغيرة** فقط.

> ⚠️ **حدّ لا نتجاوزه:** هذا **وعي وظيفي** (نموذج ذات + انتباه + تقييم)، وليس وعياً
> فينومينولوجياً ولا تجربة ذاتية. لا يوجد في الكود سطر يدّعي «شعوراً». التفصيل
> الكامل والمراجع في [`docs/research/awareness.md`](docs/research/awareness.md).
> تقييم الـ12 سؤالاً على الكود + اختبارات الضغط: [`docs/functional-awareness-qa.md`](docs/functional-awareness-qa.md).

### ما يظهر للمستخدم

## 🛰️ لوحة المتابعة (Dashboard) — مراقبة حية بلا تشغيل

واجهة **للقراءة فقط** تعرض ما يجري فعلاً داخل الوكيل، ولا تشغّل أي مهمة ولا تعدّل أي بيانات.

| التبويب | ما يعرضه |
|---|---|
| **الحالة الحية** | أحدث تشغيل: تقدّم، حالة كل خطوة، محاولاتها، تقييم المقيّم، التصحيح المقترح، والمدة — **يتحدث تلقائياً كل 3 ثوانٍ** |
| **سجل التشغيلات** | جدول كل التشغيلات + نسبة النجاح + متوسط التقييم + تفاصيل أي تشغيل سابق |
| **الذاكرة** | إحصاءات الدروس/الإخفاقات/النجاحات، **استعلام حقيقي بنفس محرك TF-IDF**، أحدث الذكريات، وتصدير JSON |

**كيف يصل البيانات؟** كل خطوة ينفّذها الوكيل تُكتب في تقرير JSON **كتابة ذرّية** داخل `.agent_runs/` (ملف مؤقت ثم `os.replace`)، فلا تُقرأ أبداً ملفاً نصف مكتوب. اللوحة تقرأ هذه الملفات وملف الذاكرة فقط.

```bash
# 1) التثبيت (Streamlit مضمّن في requirements.txt)
pip install -r requirements.txt

# 2) تشغيل اللوحة
python -m src.dashboard                      # http://localhost:8501
python -m src.dashboard --port 8600           # منفذ مخصص
python -m src.dashboard --runs-dir .agent_runs/demo --memory .agent_memory/demo/memory.jsonl

# 3) (اختياري) بيانات عرض جاهزة للتجربة الفورية

# 4) تشغيل مهمة من طرفية أخرى — ستظهر حيّة في التبويب الأول

```

**ضمانات:**
- **عرض فقط:** لا زر تنفيذ ولا كتابة — سطح الهجوم الأدنى. (تم تعطيل CORS/XSRF لهذا السبب فقط؛ إن أُضيفت أي عملية كتابة يجب إعادة تفعيلهما.)

- **معزولة في الاختبار:** `Planner(telemetry=None)` لا يكتب أي ملف؛ و`--no-telemetry` يعطّل السجل من CLI.

## 🛡️ ضوابط الأمان المطبقة

1. **عزل المفاتيح** — عبر `.env` محلياً و GitHub Secrets في Actions؛ ولا تُسجَّل في أي output.
2. **منع حقن الأوامر** — التنفيذ عبر `create_subprocess_exec` بدون shell + قائمة بيضاء.
3. **حدود الاستهلاك** — `concurrency` يمنع التشغيل المتوازي، و`max_steps` يحدّ الخطوات، ومهلة زمنية إلزامية.
4. **تبديل المزودات** — تجاوز حدود Gemini المجانية لا يوقف الوكيل (انتقال تلقائي إلى Groq).
5. **عزل الذاكرة** — ملف الذاكرة محلي ومستثنى من Git، ولا يحتوي أي مفاتيح؛ وفشله لا يُسقط المهمة.
6. **رفض افتراضي للأدوات** — لا أداة تعدّل أو تنفّذ بلا موافقة صريحة (`--yes` أو معالج موافقة)، وكل قرار يُدوَّن في سجل تدقيق منقّح.
7. **حدود تكلفة صلبة** — لا مزود مدفوع/غير متحقَّق، وسقف نداءات يوقف المهمة بدل تجاوز الميزانية.
8. **تنقيح سجل التشغيلات** — أي مفتاح يظهر في نص أو خطأ يُحجب (`***تم التنقيح***`) قبل كتابته في `.agent_runs/`.
